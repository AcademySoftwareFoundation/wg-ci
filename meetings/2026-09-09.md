## New items

* GPU runner NVIDIA driver update
  * ubuntu-20.04-gpu-t4-4c-16g-176h larger runner is using `NVIDIA GPU-Optimized VMI` NVIDIA-maintained "partner image"
  * Larger runners created from a partner image by default "float" to latest version of the image.
  * `NVIDIA GPU-Optimized VMI` currently running Ubuntu 24.04 and NVIDIA Driver 590.48.01, even though the [release notes](https://docs.nvidia.com/ngc/ngc-deploy-public-cloud/ngc-azure/index.html#azure-vmi) still show latest with Ubuntu 22.04 and NVIDIA driver 550.127.05
  * Larger runner label somewhat misleading:
    * Ubuntu version rolls with updates to partner image (should it be "ubuntu-latest-gpu-...")
    * 16G refers to GPU VRAM, VM has 28GB RAM
    * Likely similar for non-GPU larger runners
  * Rolling back CUDA to 13.1.2 in 2027.1 images allows container image to start up on T4 runners (2027.1 images re-released)
  * Larger Runners also support custom images:
    * Start with a partner image
    * Add the software you want
    * Snapshot to custom image
    * Custom images generate storage costs, have to manage all updates yourself, not desirable
    * But an option if we ever have to have different "system" software (NVIDIA driver, Docker version, NVIDIA container toolkit)
  * Documented in [ASWF CI Wiki](https://lf-aswf.atlassian.net/wiki/spaces/CIWG/pages/11436353/GitHub#GPU-larger-runner-images-and-NVIDIA-driver-versions)

* CMake project NAMESPACE for targets
  * Not every project uses the NAMESPACE option when calling install()
  * Results in un-namedspaced CMake symbols, for instance `MaterialXCore` instead of `MaterialX::MaterialXCore`
  * Can be worked around by adding aliases
  * Should ASWF projects be suggested (required?) to adopt namespacing for CMake targets?
  * Considered [best practice for Modern CMake](https://www.kitware.com/psa-your-package-name-and-target-namespace-should-match/)
  * More generally, would a "Cmake Symposium" to seek CMake unification and best practices across ASWF projects make sense? And/or point an LLM at every ASWF project and ask for a critique (similar to "Project Health Check")
